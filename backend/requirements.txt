Разработка проекта по данному техническому заданию (ТЗ) требует четкого понимания архитектуры, функциональных и нефункциональных требований, а также этапов реализации. Давайте разберем, как можно развернуть этот проект, следуя ТЗ.

### 1. Понимание проекта

Проект представляет собой веб-интерфейс для взаимодействия с различными моделями ИИ через API. Основная цель — создать единый чат-центр, который будет поддерживать несколько провайдеров и обеспечивать возможность переключения между моделями без потери истории.

### 2. Архитектура системы

Система будет состоять из трех основных уровней:
- **Фронтенд**: веб-интерфейс, который будет взаимодействовать с пользователем.
- **Бэкенд**: серверная часть, которая будет обрабатывать запросы и взаимодействовать с API провайдеров.
- **Адаптеры провайдеров**: модули, которые будут обеспечивать взаимодействие с различными моделями ИИ.

### 3. Этапы реализации

#### Этап 1: Веб-пилот

На этом этапе необходимо реализовать базовую функциональность:
- **Чат-окно**: интерфейс для ввода сообщений и отображения истории.
- **Потоковый ответ**: реализация потокового ответа от провайдера DeepSeek.
- **История**: хранение истории в формате JSONL.
- **Сборка контекста**: управление контекстом сообщений с учетом лимитов токенов.

#### Этап 2 и далее

На следующих этапах планируется добавление новых функций, таких как выбор модели, поддержка нескольких провайдеров, дебаты моделей и многопользовательский режим.

### 4. Технологический стек

Выбор технологий может быть следующим:
- **Фронтенд**: React или Vue.js для создания интерактивного интерфейса.
- **Бэкенд**: Python с FastAPI или Node.js с Express/Nest для обработки запросов.
- **Стриминг**: использование SSE (Server-Sent Events) или WebSocket для потоковой передачи данных.
- **Формат истории**: JSONL для хранения сообщений.

### 5. Реализация

#### Фронтенд

1. Создать компонент для чата с полем ввода и кнопкой "Отправить".
2. Реализовать отображение сообщений в реальном времени.
3. Обработать рендеринг Markdown и LaTeX.

#### Бэкенд

1. Настроить маршруты для обработки запросов:
   - `POST /chat/send` для отправки сообщений.
   - `GET /history` для получения истории.
   - `GET /health` для проверки состояния сервера.
2. Реализовать логику для работы с адаптером DeepSeek.
3. Обработать ошибки и обеспечить устойчивость системы.

#### Адаптер

1. Создать адаптер для DeepSeek, реализующий необходимые методы (например, `stream_chat`, `estimate_tokens`).
2. Обеспечить корректную передачу данных и обработку ответов от API.

### 6. Тестирование

Необходимо провести тестирование на соответствие критериям приемки:
- Проверить базовый диалог и отображение истории.
- Убедиться, что система корректно обрабатывает длинные истории и ошибки.
- Проверить рендеринг математических формул и кодов.

### 7. Документация

Подготовить документацию, включая:
- README с инструкциями по установке и запуску.
- Пример конфигурации и истории.
